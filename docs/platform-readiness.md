# 多端基础与后续接入

本次复核日期：2026-10-09。参考 wl-mbase 的实际宿主接入，以及 Robot H5 / Robot_H5_Core 的主题和桥接协议。下面区分源码能力、构建验证和实际发布，避免将模板入口视为已接入的服务。

## 本次已收敛的缺口

| 问题                                                   | 已落地的处理                                                                                                   |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 主题、语言、网页和图片操作菜单仍使用系统菜单，视觉分裂 | `uni.showActionSheet` 纳入统一反馈层；带标题、当前项、说明、遮罩取消、键盘操作，保留 `tapIndex` 与回调/Promise |

| 组件库英文标题灰色                                     | 复用 `page-eyebrow` 的品牌色；Modal、操作菜单、日历、级联选择和数字键盘共享浮层令牌                            |
| H5 扫码被编译条件一律禁用                              | 页面按实际能力注册启用；H5 默认不支持扫码，宿主提供扫描方法后可使用，相册能力另行声明                          |
| 宿主能力只能整套覆盖，缺少就绪和撤销                   | 支持部分注册、一次并发初始化、初始化超时、撤销及统一错误；设备识别仅用于诊断                                   |
| 定位坐标类型不明确                                     | 原生 `gcj02` 与浏览器 `wgs84` 分别返回 `coordinateSystem`，业务不得直接混用                                    |
| 页面请求引用滞留，退避重试可能挂到新页面               | 完成后释放引用；固定请求来源页，离开页面也能取消等待重试                                                       |
| 上传业务 401 没有统一处理                              | 上传沿用请求协议与会话清理、登录回跳                                                                           |
| 续传暂停、删除及切号存在竞态                           | 共用执行状态，重复启动合并，删除后迟到响应不复活；任务绑定账号与环境                                           |
| 测试/预发布开发服务也自动启用 Mock                     | 显式 `VITE_MOCK_ENABLED`，演示和真实联调分开；生产构建强制排除 Mock                                            |
| 更新校验可跳过，版本回退变量无实际来源                 | 清单强制 SHA-256，使用真实 manifest 版本回退；读取文件或摘要能力缺失即失败                                     |
| CI 重跑单测且遗漏 App 资源构建                         | 契约与单测只跑一次；增加 App 资源构建门禁                                                                      |
| 设置提供无效果的通知/字号切换                          | 通知显示暂未启用；字号显示实际标准，不再提示未生效的切换成功                                                   |

## 新宿主的接入边界

业务使用 `platform.scanCode/getLocation/takePhoto`。初始化位置注册实际实现，而非在页面中直接调用钉钉或 PDA SDK：

```ts
const dispose = registerPlatformAdapter({
  provider: 'enterprise-device',
  ready: () => deviceBridge.ready(),
  readyTimeoutMs: 8000,
  capabilities: {
    scanCode: source => deviceBridge.scanCode(source),
  },
  capabilitiesSupport: { scanFromAlbum: false },
})
// 宿主销毁或会话撤销时清理。
dispose()
```

`deviceBridge` 是接入方提供的真实实现，不是框架内置 SDK。`getPlatformEnvironment()` 用于诊断运行端和容器；`getPlatformCapabilityStatus()` 用于控制入口。扫码相册能力必须单独声明，不能因为存在相机扫描方法就默认支持。

`getPlatformCapabilities()` 保留方法签名，但返回动态统一入口；外部若保存旧实现对象或依赖对象身份，应改为按注册/撤销管理宿主生命周期。

## 后续推进顺序与验收条件

1. **正式后端与身份**：确定真实 API、环境、登录兑换及权限来源；关闭 Mock 后完成登录、401、切号、刷新和失败重试。钉钉及微信 code 必须由后端兑换，不把“拿到 code”当成登录成功。
2. **Robot H5 宿主协议**：复用 wl-mbase 的 capability、navigation、environment、page-state 版本化 envelope，与 Robot_H5_Core 的 mbase transport 对齐。明确请求 ID、来源/子应用白名单、就绪、超时、取消、会话撤销和返回行为；验收 App WebView 与 H5 iframe 两条通道，避免双头部。
3. **PDA 专项**：先选设备矩阵，再接相机、键盘输入或厂商扫描广播。按实际 WebView 版本确认编译目标；验收连续扫描、输入焦点、实体返回键、横屏、软键盘、离线及恢复，不从 Android 标签推断设备可用。
4. **上传闭环**：当前状态机没有默认页面或启动入口。补文件持久保存、服务端断点查询/校准、联网恢复与业务归档；实际 `/upload/init|chunk|complete` 接口必须联调。任务 `endpoint` 是分类标识，不能改变传输 URL；无归属 v1 任务保留但不自动认领新账号。
5. **App 更新发布**：本次只验证清单/版本/文件校验逻辑，未执行真实下载或安装。需要可信更新服务、渠道与包匹配、强更恢复、文件读取和安装真机验收；关于页的在线更新仍未接入。
6. **通知与实时消息**：接实际推送/消息服务后再开放设置。当前 WebSocket hook 未被业务消费，接入前需解决重复连接、旧 socket 回调覆盖新连接、队列上限及会话撤销；不将本机偏好存储当成系统推送能力。
7. **稳定性与诊断**：复用 appStore 网络状态，避免新页面再建一套不同判定；错误上报接已有脱敏 reporter，补版本、运行端与网络上下文。字号应先统一相对排版和组件令牌，再开放全应用切换。

## 验证范围

自动验证入口为 `pnpm check:quality`、`pnpm build:h5`、`pnpm build:wx`、`pnpm build:app` 和 `pnpm check:budget`。浏览器覆盖菜单选择/取消、输入弹窗、混合队列、部门回填、标题色、深浅主题、减少动态效果、小屏/桌面及测试适配器注册/撤销。

浏览器注入扫描方法用于检验框架扩展路径，不是钉钉/PDA SDK 验收。微信开发者工具、正式 App 包和具体 PDA 真机结果应单独记录；本次不以资源编译成功替代真机验收。

验收依据为本项目自身的检查脚本、uni-app 条件编译、跨端构建和实际运行。工作区 Kit 规则主要面向 PC 管理端子应用，其扫描提示不作为移动端缺陷数量或整改依据。项目 Lint 保留既有检查脚本中的 4 条 `no-await-in-loop` 警告。
